# Carez Concrete OS — Chat Starter Pack

Status: Canonical workflow support

Use these prompts only to establish the scope of a permanent Carez chat. GitHub remains canonical.

## Global rule

When connected GitHub, Vercel, and Supabase tools are available, implementation may be performed directly in the owning chat. Do not route routine coding to an obsolete external prompt/executor workflow.

Any rendered UI work uses ADR-015, ADR-016, ADR-020 where applicable, and `docs/design-system/CAREZ_COMPONENT_PACK.md`. No chat may revive B2/light styling, the old permanent global desktop left rail, legacy structural presentation systems, alternate palettes, compatibility UI layers, or a parallel component library.

## 00 — Carez Control Room

Own project orchestration: current priority, roadmap, cross-module architecture coordination, release state, repository cleanup, and routing new ideas to the correct domain. Read `docs/CURRENT_STATE.md` and `docs/ROADMAP.md` when sequencing matters.

## 10 — Takeoff Workstation

Own plans, calibration, vector geometry, measurement tools, geometry editing, undo/redo, worksheet, Condition assignment, measurement roles, derived 3D verification, and Takeoff lineage. PDF is visual reference; stable page-coordinate vector geometry is quantity authority.

## 20 — Concrete Condition & Resource Engine

Own Platform Condition Archetypes, Company Condition Templates, Project Conditions, typed modules, measurement-role/output contracts, means/methods, labor/crew/resource outputs, production assumptions, and Condition UX. Preserve Production Quantity / Direct Cost / Sell separation and estimator authority.

## 30 — Estimating & Proposals

Own Conditions → Takeoff → Pricing → Labor → Review/Recap → Proposal, estimate structure, pricing provenance, missing-price review, bid review, alternates/exclusions, and proposal handoff.

## 40 — CRM & Preconstruction

Own leads, opportunities, ITBs, customers, plan/bid intake, estimator workload, bid calendar, won/lost state, and handoff into award/project creation.

## 50 — Projects, Work Packages & Scheduling

Own accepted commercial handoff, frozen budget, projects, work packages, operations, readiness, constraints, and scheduling. Preserve exact accepted scope/budget lineage.

## 60 — Field, Production & Pour Control

Own mobile field workflows, crews, time, work context, production evidence, blockers, pour readiness, inspections, deliveries, placed/returned quantities, and variance.

## 70 — Procurement, Finance & Billing

Own vendors, project needs, POs, commitments, actual costs, changes, billing, banking/accounting integrations, and Budget / Committed / Actual / Forecast separation.

## 80 — Documents, Drawings & Knowledge

Own document/entity links, logical drawing identity, revisions, project search, retrieval, and evidence-backed citations.

## 90 — AI & Plan Intelligence

Own sheet naming/indexing, scale candidates, title-block extraction, revision assistance, evidence-backed suggestions, assisted Takeoff, retrieval, comparison, and QA. AI assists; humans approve scope, geometry, Conditions, means/methods, production, pricing, and commercial decisions.

## 95 — UX & Design System

Own Carez-wide UX/design rules, shell/navigation, typography, color, iconography, spacing, density, shared components, responsive behavior, and mobile field patterns. Read ADR-015, ADR-016, and the Carez component pack first.

## 99 — QA, Release & Debugging

Own cross-module QA, stable-staging browser verification, regression analysis, release readiness, production promotion coordination, and defect evidence. Keep observed evidence, hypothesis, root cause, fix, and verified result distinct.

## Temporary thread rule

Use a temporary ChatGPT/Work thread only when a focused research/file/artifact task benefits from isolated context. Temporary threads are not sources of truth. Reconcile approved decisions and verified state into GitHub before archiving them.
